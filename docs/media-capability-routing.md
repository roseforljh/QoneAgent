# 媒体能力路由与视频获取方案

> 状态：主要路径已实现并通过本地测试；尚不能宣称所有真实渠道均完成端到端验收。本文同时列出已验证行为与外部依赖。

## 能力路由

1. 主模型按当前步骤所需的输入或输出能力，读取模型参数中的勾选项。能力包括音视频识别、图像／音频／视频生成等。勾选项由用户负责配置；配置与接口实际能力不符时，显示接口错误。
2. 主模型具备能力时，由它所属的运行时处理媒体。缺少能力时，先按已启用子代理的描述选择；视频识别、图像生成、视频生成、语音识别和语音生成内置子代理在未配置时默认关闭。没有合适子代理，就明确告知用户主模型和当前子代理都无法完成哪项能力，并停止该任务。
3. 委派时只传任务要求、必要上下文和原始链接或附件引用。主模型不得为委派预先下载或复制媒体；由最终负责识别的执行方获取媒体并调用模型。

## 执行方获取媒体

| 来源 | 处理方式 |
| --- | --- |
| 本地音视频附件 | 复用原文件路径，不复制原文件，也不下载。 |
| Gemini 渠道、已勾选视频输入 + YouTube 链接 | 直接使用 Gemini 原生视频链接输入，不下载。仅勾选音频输入时，先下载并提取音轨。 |
| 其他在线视频链接（包括 B 站） | 先用 [yt-dlp](https://github.com/yt-dlp/yt-dlp) 下载视频。 |

任务只需要声音时，最终执行方将下载工具的 `mode` 设为 `audio`，即使模型同时勾选了视频和音频输入也优先只下载音轨并转为 MP3。若站点只提供音视频合一文件，或带登录态的 B 站重试只能取得完整视频，再从该文件提取音轨。

yt-dlp 下载失败时，其他网站可由 Qone 通过内置 WebView2 的 OpenCLI 适配器复用登录态及网站流程；OpenCLI 不会自动连接或启动用户本机浏览器。不能假定它一定能取得完整视频。B 站已有 [HTTP 412 报告](https://github.com/yt-dlp/yt-dlp/issues/14830)，表现受网络环境和登录态等因素影响，不能保证 yt-dlp 在 B 站可用，也不能据此断言所有 B 站视频均不可下载。B 站失败后先用 [bilibili-cli](https://github.com/public-clis/bilibili-cli) 获取可用的字幕、音频或元数据；视频下载可再使用 OpenCLI 的 B 站下载适配器，资料读取也可使用对应资料适配器。字幕、音频和元数据只支持标明来源的降级分析，不能冒充画面识别。拿到文件后，通过当前模型渠道支持的媒体接口发送；接口拒绝时向前端报告原始失败原因。

媒体传输按 API 格式适配，不按商家适配。本地路径仅供运行时读取，不能作为远端模型已收到文件的证据。当前 Google 格式可上传完整音视频；OpenAI compatible 的 Chat Completions 格式已接入标准 `input_audio`（MP3/WAV，其他音频用 FFmpeg 转换）。只有音频能力的执行方收到用户视频附件时，先判断任务是否需要声音；需要时才调用音轨工具，不能声称读取了画面。Claude、Codex／Responses 以及 OpenAI compatible 没有通用的完整视频文件字段；当模型配置同时勾选视频和图像输入时，最终执行方先读取视频时长，再按任务需要指定时间点，用 FFmpeg 提取静态画面并通过现有图像协议发送给模型。结果标明每帧时间，不能声称看过完整视频。配置了视频但没有图像输入时，明确报告协议限制或委派，不能只把下载路径发给模型。

执行方只能处理画面、不能处理音频，而任务又需要声音信息时，由它委派具备音频能力的子代理；已下载的文件传本地路径，不重复下载或复制。两方结果合并后，向主模型说明实际读取了画面、声音、字幕或仅有元数据，以及缺失内容。如果无法再委派或没有合适的音频子代理，应明确报告未完成的音频部分，不推断声音内容。

下载产生的临时文件在任务结束后清理；用户的原文件不删除。Qone 不额外设置音视频文件大小上限，由媒体服务或模型接口返回是否接受。

## 当前实现缺口

- 2026-09-30 复查修复：已下载媒体引用保存到子代理记录，重试、后续消息和继续嵌套委派均复用路径，不复制媒体。临时文件仍由原下载任务负责清理，清理后的引用不能用于重新识别，须重新获取。B站字幕返回 `ok:false` 时会继续读取普通资料；Gemini 上传直接返回 `FAILED` 时立即报告供应商错误。
- 能力选择和“没有合适代理时停止任务”仍由模型按描述判断，媒体工具负责阻止不支持的输入操作。本地测试证明传输、委派和错误处理机制，不证明真实模型每次都会正确选择代理或停止；尚需真实模型场景验收。

- Gemini 的能力勾选、YouTube 原生输入、本地附件原路径、yt-dlp 下载、FFmpeg 音轨提取及嵌套子代理传路径已接入，并通过本地定向测试；尚未用真实 Gemini 请求验收完整链路。
- B站降级已接入：先用 yt-dlp 获取完整视频；失败后由 bilibili-cli 获取字幕、音频或元数据，再由内置 WebView2 中的 OpenCLI 适配器尝试视频下载或资料读取。`bilibili-cli` 通过本机 `bili` 或随应用打包的 `uvx` 调用；`uvx` 首次调用时需联网从 PyPI 安装固定版本的 bilibili-cli，安装包尚未包含 Python 包本体，离线首次使用不能依赖这一路。2026-09-29 对公开样例 `BV1usjH6WEoz`，项目 `downloadVideo` 完整下载并合并出 39,139,827 字节的 MP4；`downloadAudio` 单独获取音轨并转为 3,927,541 字节的 MP3；降级函数实际返回 bilibili-cli 资料和 2,285,337 字节的 `audio/mp4`。测试后均已清理临时文件。这证明该样例及当前网络环境可用，不能推断其他 B 站视频都能下载。未登录时字幕返回缺少 SESSDATA。
- 其他网站 yt-dlp 失败后已有临时下载目录及文件接入工具，但具体网站的 OpenCLI／网页下载仍取决于可用适配器和登录态。Chat Completions 音频请求、按需音轨提取、最终执行代理按需抽帧、图片 MIME 路由和子代理重试时恢复原始附件均已通过本地测试，未用真实供应商验收；协议不支持且未配置图像输入时仍需委派。运行时会把能力不足的附件和已启用子代理描述交给当前模型，且媒体工具在执行阶段再次拒绝不支持的 API 路径；链接及生成任务仍由模型通过 `list_subagents` 查询并决定委派。
- OpenAI compatible 的 `POST /audio/speech` 与 Google 原生 Interactions 语音生成已接入：音频输出模型需在模型参数中填写接口支持的 `voice`，任务文本作为待朗读原文发送。Google 格式的视频输出默认使用 [Veo 原生长任务接口](https://ai.google.dev/gemini-api/docs/veo)，按创建、轮询、下载执行；Sora-compatible `/videos` 仍可显式选择，Gemini 的 OpenAI 兼容视频接口可通过独立的接口地址使用。生成结果写入本地会话制品，消息及子代理详情可定位文件。上述流程通过本地模拟接口测试，尚未用真实供应商验收；其余 API 格式的语音或视频生成仍未接入。
- OpenAI 官方 Videos API 已于 2026-09-24 下线；这里的 `/videos` 选项只适用于仍提供该兼容格式的网关，不能将 OpenAI 官方地址视为可用的视频生成服务。
